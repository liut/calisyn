# 语料文档管理面板

## Summary

为 Calisyn 前端新增一个仅对高级权限用户开放的独立语料管理页面：列表搜索/分页浏览语料文档，抽屉内查看和编辑，支持删除，并预留 CSV 导入入口（导入交互待后端异步方案确定后补齐）。

---

## Problem Frame

Morrigan 后端刚通过 f09ab7a 提供语料文档的 Web API（列表/详情/更新/删除），但 Calisyn 前端目前没有任何入口可以看到或维护语料库。现在语料维护只能靠命令行 `morrigan import docs.csv` 或直接操作数据库，部署者看不到库里的文档内容、无法核对错误条目，也无法在线修正。

语料库是知识库问答的地基，文档错误会直接污染回答质量；缺少可见性和在线管理手段，意味着修正一条错误文档的成本很高——要么重新跑导入，要么摸黑改库。

---

## Actors

- A1. 高级权限用户（语料管理者）：部署方管理员/keeper，能进入管理页面并编辑、删除文档。
- A2. 普通登录用户：无高级权限，看不到管理入口，不能访问管理页面。

---

## Key Flows

- F1. 浏览与搜索语料列表
  - **Trigger:** 高级用户点击侧边栏语料入口进入管理页面
  - **Actors:** A1
  - **Steps:** 进入页面 → 列表加载（分页+总数）→ 输入关键词搜索（匹配标题/小节/内容）→ 翻页/排序查看
  - **Outcome:** 用户能看到语料库全貌并定位目标文档
  - **Covered by:** R1, R5, R6, R7
- F2. 查看并编辑文档
  - **Trigger:** 用户在列表点击某行
  - **Actors:** A1
  - **Steps:** 点击行 → 抽屉展示完整内容与元信息 → 修改字段 → 保存 → 列表刷新
  - **Outcome:** 文档内容可在线查看和修正；保存失败时给出错误提示且不丢失编辑内容
  - **Covered by:** R9, R10
- F3. 删除文档
  - **Trigger:** 用户在抽屉或行操作中点击删除
  - **Actors:** A1
  - **Steps:** 点击删除 → 二次确认 → 调用删除 → 从列表移除
  - **Outcome:** 文档及其关联向量由后端清理；删除失败时给出提示
  - **Covered by:** R11
- F4. CSV 导入（占位）
  - **Trigger:** 用户点击导入按钮
  - **Actors:** A1
  - **Steps:** 点击导入按钮 → 当前为占位状态（不可用并说明原因）→ 后端异步导入方案确定后补充上传/进度/结果交互
  - **Outcome:** v1 提供可见入口但不承诺可用；导入能力交付时不改页面框架
  - **Covered by:** R12

---

## Requirements

**入口与权限**
- R1. 新增独立语料管理页面，作为聊天应用内的独立路由，从聊天界面侧边栏底部新增图标入口进入。
- R2. 页面入口与路由仅对高级权限用户可见/可达（以会话返回的 `data.keeper` 为准）；普通用户看不到入口，直接访问路由时被引导回聊天页。
- R3. 编辑、删除操作按钮仅对 `data.keeper` 为 true 的用户显示；入口可见性与后端实际鉴权保持一致。
- R4. 对后端返回的 403/401 等鉴权失败给出明确错误提示，不出现静默失败或空白页。

**列表**
- R5. 列表展示语料文档：标题、小节/类别、内容摘要、更新时间，并显示分页与总数。
- R6. 提供关键词搜索，同时匹配标题、小节、内容。
- R7. 支持后端允许的字段排序（如标题、小节、更新时间）。
- R8. 空列表、加载中、加载失败均有对应状态展示。

**详情与编辑**
- R9. 点击列表行打开抽屉详情：完整内容、元信息（如创建/更新时间）；长文本可滚动。
- R10. 抽屉内可编辑标题/小节/内容并保存；保存成功后刷新列表对应行。
- R11. 删除操作需二次确认，删除成功后从列表移除。

**CSV 导入（占位）**
- R12. 页面提供 CSV 导入入口（按钮及文案占位）；后端异步导入方案（含端点契约）确定前按钮不可用并提示原因。导入交互的具体形态（上传/预览/进度/结果）由后续迭代补齐，不在 v1 承诺。

**通用**
- R13. 页面文案接入现有多语言体系。
- R14. 复用现有请求封装与错误处理模式，不引入新的请求基础设施。

## Acceptance Examples

- AE1. **Covers R2.** 普通用户会话下：侧边栏看不到语料入口；手动输入管理页地址被重定向回聊天页。
- AE2. **Covers R3, R4.** 会话 `data.keeper` 为 true 的用户看到编辑/删除按钮；为 false 的用户即使拿到入口，调用更新/删除返回 403 时页面给出明确提示，且按钮不显示。
- AE3. **Covers R6.** 输入关键词后列表只保留标题、小节或内容中包含该词的文档；清空关键词恢复全量列表。
- AE4. **Covers R9, R10.** 点击行打开抽屉显示完整内容；修改标题并保存后，列表该行的标题立即更新；后端失败时抽屉保留当前编辑内容并提示。
- AE5. **Covers R11.** 点击删除弹出确认，确认后文档从列表消失；取消则不发生任何变化。
- AE6. **Covers R12.** 导入端点未就绪时，导入按钮不可点击并附说明；端点就绪后按钮可点击并进入已设计的导入流程。

---

## Success Criteria

- 高级用户无需命令行或数据库即可完成语料文档的浏览、搜索、查看、修正与删除。
- 前端对权限的展示与后端实际鉴权一致（有按钮的用户确实能操作，没权限的用户看不到按钮且后端 403 有兜底提示）。
- 需求文档足以让 ce-plan 直接产出实现方案，无需再补产品决策。

---

## Scope Boundaries

- 不做手动"新建文档"表单——后端目前无 create 端点，新增统一走 CSV 导入；手动新建列为后续项。
- 不做 CSV 导入的完整交互（上传/预览/进度/结果）——等后端异步方案确定后补。
- 不做 CSV 导出或模板下载——本次未要求，可在后续迭代补充。
- 不改动 morrigan 后端 corpus API 本体（f09ab7a 已提供 R/U/D；导入端点由后端侧另行推进）。

---

## Key Decisions

- 独立管理页面而非设置弹窗：表格+长文本编辑需要更大空间，语料管理也不是个人设置项。
- 仅高级权限用户可见：语料维护是部署方管理行为，不是人人可查的共享资料。
- 权限信号采用会话新增的 `data.keeper` 布尔字段：与后端 keeper 判定对齐，前端无需解析角色列表。
- 新增统一走 CSV 导入：与后端现状（无 create 端点）对齐，避免为单文档表单额外开接口。
- 表格+抽屉详情：长文本在抽屉中比弹窗舒展，列表保持紧凑。

---

## Dependencies / Assumptions

- morrigan f09ab7a 已提供语料文档列表/详情/更新/删除 Web API，前端按该接口开发（已验证：`../morrigan/docs/corpus.yaml` 中 `webapi.uris` 配置了 Document 的 R/U/D）。
- CSV 导入 Web 端点由后端侧新增，可能采用异步处理；前端先按"导入入口+占位"设计，端点契约确定后再补齐交互。
- 前端需要能携带 morrigan 认可的认证凭证访问语料 API；前端 `/api` 代理与 morrigan 的连通方式（直连或经 Express 转发）以部署为准。
- morrigan 会话接口将新增 `data.keeper` 布尔字段，作为前端高级权限与编辑/删除按钮显示的依据；前端会话类型需同步新增该字段。
