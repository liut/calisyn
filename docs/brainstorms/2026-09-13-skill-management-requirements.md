# 技能浏览与管理面板

## Summary

为 Calisyn 新增一个对所有登录用户开放的技能页面：以表格浏览自己可见的技能（投放到频道的 + 自己创建的），支持关键字搜索、分页与归属筛选，点行开抽屉查看 SKILL.md 全文；通过表单创建技能，创建者可编辑、删除自己的技能。文件导入与 URL 安装不在本版范围。

---

## Problem Frame

morrigan v0.9.0（2026-09-10）已经交付技能的完整 REST：用户级接口按「频道投放 ∪ 自己创建」判定可见性，另有 keeper 专属的全量管理接口。但 Calisyn 前端没有任何技能入口——`src/` 下不存在技能相关代码，侧边栏也没有入口。

同时技能表当前是空的，且没有任何可用的创建通道：morrigan 的 CLI 只有文档导入/导出与 swagger 能力导入，没有技能相关命令，要建一个技能只能手写 curl 打接口或直接改库。

两层后果叠在一起：技能能力虽然上了后端，却没有一个用户能通过界面获得它——既看不到组织里已有的技能，也没法贡献自己的；任何人想在对话里用上技能，前提都是先会 curl。技能是用户级内容（可见范围由频道投放与归属决定，不牵动全局回答质量），缺入口让这个特性停留在「后端已支持、产品未交付」。

---

## Actors

- A1. 登录用户：浏览自己可见的技能与全文；创建自己的技能；编辑、删除自己创建的技能。
- A2. Keeper（管理员）：在本页面与普通用户权限相同——列表只含「频道投放 ∪ 自己创建」，没有全库视角。全量管理不在本版范围。

---

## Key Flows

- F1. 浏览与定位技能
  - **Trigger:** 用户从侧边栏进入技能页面
  - **Actors:** A1
  - **Steps:** 进入页面 → 列表加载（分页 + 总数，默认按创建时间倒序）→ 在「全部可见 / 我创建的」之间切换 → 输入关键字按技能名搜索 → 翻页/排序 → 点击行打开抽屉读全文
  - **Outcome:** 用户能看到自己可用的技能全貌，并判断某个技能做什么、何时用
  - **Covered by:** R1, R5, R6, R7, R8, R9, R14

- F2. 创建技能
  - **Trigger:** 用户点击「新建技能」（技能表为空时首屏即引导）
  - **Actors:** A1
  - **Steps:** 打开表单 → 填写技能名、描述、正文，选择投放频道（默认 web）→ 本地校验 → 提交 → 列表刷新并直接打开该技能的详情
  - **Outcome:** 新技能立即可见、可被继续维护；投放 web 后进入 Web 用户对话的技能索引
  - **Covered by:** R10, R11, R12, R13

- F3. 维护自己的技能
  - **Trigger:** 创建者在详情抽屉里点击编辑或删除
  - **Actors:** A1
  - **Steps:** 打开自己技能的详情 → 修改描述/正文/投放频道并保存（或删除并二次确认）→ 列表刷新
  - **Outcome:** 自己的技能内容始终可修正；他人技能的详情为只读
  - **Covered by:** R3, R15, R16, R17
  - **Failure / escape:** 保存失败时抽屉保留已编辑内容并提示；删除必须二次确认

## Requirements

**入口与权限**

- R1. 新增独立技能页面，作为聊天应用内的独立路由，从聊天界面侧边栏底部新增图标入口进入；该入口对所有登录用户显示。
- R2. 页面不做 keeper 分支：本页的可见范围与可操作项不随会话的 keeper 状态变化，始终以「频道投放 ∪ 自己创建」为可见集。
- R3. 编辑与删除入口仅对 `owner` 为当前登录用户的技能显示。
- R4. 鉴权失败（401/403）与请求失败给出明确错误提示，不出现静默失败或空白页。

权限矩阵（决定 R2、R3 的行为）：

| 技能归属 | 列表/详情可见 | 编辑 | 删除 |
|---|---|---|---|
| 自己创建的（含未投放） | 是 | 是 | 是 |
| 他人投放到 web 的 | 是 | — | — |
| 他人投放到 wecom/feishu 或未投放的 | 否 | — | — |
| keeper 视角 | 同上，无额外特权 | — | — |

**列表与定位**

- R5. 列表展示技能的名称、描述、投放频道、更新时间与归属标记（是否自己创建），并显示分页与总数。
- R6. 默认按创建时间倒序；支持后端允许的字段排序，交互与语料面板一致。
- R7. 提供关键字搜索，按技能名匹配（后端的模糊匹配只定义在 name 上，描述与正文不可搜）。
- R8. 提供归属筛选：「全部可见」与「我创建的」两个视图，默认「全部可见」。
- R9. 列表的空、加载中、加载失败三态齐备；技能表为空时首屏是创建引导（说明技能是什么、模型如何按需加载、给出创建入口），而不是一句「暂无数据」。

**创建**

- R10. 「新建技能」用弹出表单收集：技能名、描述、正文、投放频道（单选，默认 web）。
- R11. 表单按后端规则做本地校验：技能名格式与长度、描述长度上限、正文 frontmatter 中的 name/description 与表单字段一致；frontmatter 由表单自动拼装，用户不需要手写 YAML。
- R12. 创建成功后刷新列表、保证新技能可见，并直接打开该技能的详情。
- R13. 创建失败时保留已填内容并给出可理解的原因；名称被占用时说明该名称可能属于他人未公开的技能，而不是只回显后端原文。

**详情与维护**

- R14. 点击列表行打开抽屉：展示技能全文（Markdown）、元信息（创建/更新时间、归属、投放频道）与资源文件清单；清单为空时明确说明不显示空白块。
- R15. 创建者可在抽屉内编辑描述、正文与投放频道并保存；保存成功后刷新列表对应行。
- R16. 创建者可删除自己的技能，删除需二次确认，成功后从列表移除。
- R17. 技能名创建后不可变更（后端不支持改名），编辑界面不提供改名并说明原因。

**通用**

- R18. 页面文案接入现有多语言体系，所有 locale 文件同步补齐，并满足现有的语言键一致性测试。
- R19. 复用现有请求封装、错误处理与权限守卫模式，不引入新的请求基础设施。

## Acceptance Examples

- AE1. **Covers R1, R2.** 非 keeper 的登录用户从侧边栏能进入技能页；keeper 进入同一页面时看到相同的列表范围（都只含频道投放的与自己创建的技能），页面上不出现全库视角。
- AE2. **Covers R3, R14.** 列表里同时有「我创建的」与他人投放的技能时：只有自己那几行出现编辑/删除入口；对他人技能打开的抽屉只读，没有保存与删除动作。
- AE3. **Covers R7, R8.** 切到「我创建的」后列表只剩自己创建的技能；搜索只按技能名过滤，输入只出现在描述或正文里的词不会命中。
- AE4. **Covers R9.** 技能表为空时首次进入页面，看到的是创建引导与创建入口，而不是空白表格或「暂无数据」。
- AE5. **Covers R11, R12.** 用表单新建一个技能并保持默认投放 web：提交后列表出现该技能且详情自动打开；其正文带有与表单字段一致的 frontmatter，后端校验通过。
- AE6. **Covers R13.** 用一个已被他人未公开技能占用的名称创建时，页面给出「该名称已被占用」的说明，并保留已填内容。
- AE7. **Covers R15.** 在抽屉里修改描述并保存后，列表该行的描述立即更新；后端失败时抽屉保留编辑内容并提示。
- AE8. **Covers R16.** 点击删除弹出二次确认；确认后技能从列表消失，取消则不发生任何变化。

## Success Criteria

- 用户不需要 curl 或改库就能完成技能的新建、查看、修正与删除；显式投放到 web 的技能对所有登录用户可见。
- 新技能创建并投放 web 后进入 Web 对话的技能索引（默认按时间最近取 N 条，N 可配置），模型可经 `skill_read` 加载全文。
- 前端展示的权限与后端实际鉴权一致：没有编辑/删除入口的用户确实无权操作，越权或请求失败有兜底提示。
- 需求文档足以让 ce-plan 直接产出实现方案，无需再补产品决策。

---

## Scope Boundaries

- 不做文件导入与 URL 安装（SKILL.md / .zip / .skill）：morrigan 没有相应端点，且用户级创建接口只接受文本文件内容，二进制资源无法随包上传。
- 不做资源文件的上传、下载与内容查看：后端没有读取单个资源文件内容的 HTTP 端点，该能力只存在于对话内置工具里。
- 不做多频道（多选）投放：后端枚举目前只能编解码单值，掩码的编解码与按频道过滤都需要后端改动，前端无法单独交付。
- 不打通「对话里圈选技能」（对话请求携带技能清单）：本版只交付页面与内容，不改对话链路。
- 不接入 keeper 全量管理接口，不提供全库视图（列表接口强制只看可见）。
- 不做描述/正文搜索、技能改名、版本化、技能市场与导入导出。
- 不改动 morrigan 后端：本版全部是 Calisyn 前端工作。

## Key Decisions

- 面向所有登录用户，而非语料页那样的 keeper-only：技能是用户级内容（可见性 = 频道投放 ∪ 自己创建），影响的是自己的对话范围；语料 keeper-only 是因为文档错误会污染全局回答质量。
- 复用语料面板的结构（表格 + 抽屉），另加归属视图与空态创建引导：这套结构在本仓库已验证，边际成本最低；而技能表当前为空，空态是常态而非异常。
- 空表首屏即创建引导：这版的主要价值是「能把技能建出来」，首屏不该是一句「暂无数据」。
- v1 只做表单创建，SKILL.md 解析成表单字段后置：先把「建得出来、看得见、改得动」的闭环跑通，文件解析是独立的一块。
- 投放频道默认 web，而不是沿用后端的私有默认：可见性规则是「投放的频道 ∪ 自己创建」，若默认私有，页面上的浏览在他人可见之前没有对象。
- 投放用单选而非多选：位掩码在存储与可见性判断上已经通了，但枚举编解码与频道过滤只支持单值，多选必须先把后端契约补上。
- frontmatter 由表单自动拼装：后端要求正文自带 frontmatter 且与记录字段一致，让用户手写 YAML 会把「格式填错」变成主要失败模式。
- 编辑/删除仅限 owner：与后端更新/删除接口的 owner 校验对齐，前端只是不去提供注定失败的操作。
- 不做 keeper 视图：本版目标是把用户级能力交付出去，全库管理是另一条需求。

## Dependencies / Assumptions

- morrigan v0.9.0 已交付用户级技能接口（列表/详情/创建/更新/删除）与 keeper 专属管理接口；本版按用户级接口开发（已核实：`../morrigan/pkg/web/api/handle_skills_x.go`、`../morrigan/pkg/services/stores/skills_x.go`）。
- 列表接口只返回元数据（正文被裁剪），全文与资源文件清单需要按技能名单独取详情。
- 创建与更新必须以 JSON 提交：后端对 multipart/form 的绑定会跳过频道与文件字段，用 multipart 提交时频道会被静默忽略并落回默认值（私有）——已实测确认，不是推断。
- 技能名全局唯一且不区分可见性：撞到他人未公开的名称时后端只返回「已存在」，前端无法查明占用者。
- 会话返回的用户信息包含 `oid`，与技能的 owner 同源，前端可据此判定归属；Calisyn 现有的会话用户类型需要补该字段。
- 技能可见性与频道相关：Web 请求按 web 频道判定，因此投放 web 的技能会进入 Web 对话的技能索引（默认按时间最近取 N 条，N 可配置）。
- 前端 `/api` 与 morrigan 的连通方式（直连或经 Express 转发）以部署为准，与语料面板相同。
- 新增文案需同步全部 locale 文件，并满足现有的语言键一致性测试。

- [R3][Technical] 会话用户类型补 `oid` 字段的落点（会话响应类型与用户信息结构）。
