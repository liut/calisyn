# 记忆浏览与管理面板

## Summary

为 Calisyn 新增一个对所有登录用户开放的记忆页面：从侧边栏底部的图标入口进入，以表格浏览自己的记忆元数据，点行开抽屉读正文，并修正分类 / 内容 / 分层或删除条目。页面不做角色分支，也不提供新建；keeper 打开看到的同样是本人记忆。

---

## Problem Frame

记忆由 agent 在对话过程中写入，并在需要时经 `memory_list` / `memory_recall` 供模型读取——记忆不进系统提示（见 `../morrigan/pkg/services/agent/prompt.go` 的记忆指引），用户端没有任何可见面。写入过程没有人工复核环节：模型把用户的偏好、事实、决定记下来，记错、过期、重复的条目会一直留在库里，之后继续作为事实被召回。

此前记忆接口是生成器产物迁移来的手写文件，没有身份语义：列表可不带参数翻出全站记忆，详情、更新、删除按 ID 裸操作。morrigan 的 `feat/memory-ownership` 分支（fab00e2）补上了归属约束与五个 HTTP 接口，普通用户只能读写自己的记忆，越权返回 403、目标不存在返回 404，列表默认裁掉正文。

后端能力就位之后，Calisyn 前端仍没有任何记忆入口：`src/` 下不存在记忆相关代码，侧边栏也没有入口。用户看不到系统记住了什么，也就无法纠正错误条目或清理不再成立的旧记忆——而这些内容会持续影响对话中关于自己的回答。

---

## Actors

- A1. 登录用户：浏览自己的记忆清单，读取正文，修正分类 / 内容 / 分层，删除条目。
- A2. Keeper（管理员）：在本页面与普通用户完全一致，看到的也是本人记忆；后端具备的代查能力不在本页暴露。

---

## Key Flows

- F1. 浏览与定位记忆
  - **Trigger:** 用户从侧边栏底部进入记忆页
  - **Actors:** A1
  - **Steps:** 进入页面 → 列表加载（分页 + 总数）→ 按关键字 / 分类 / 分层筛选 → 翻页或切换排序 → 点击行打开抽屉读取正文
  - **Outcome:** 用户能看到系统记住了自己的哪些内容，并判断哪几条需要修正或删除
  - **Covered by:** R1, R2, R5, R6, R7, R8, R9, R10

- F2. 修正一条记忆
  - **Trigger:** 用户在抽屉里发现某条记忆的分类、内容或分层需要调整
  - **Actors:** A1
  - **Steps:** 打开详情 → 编辑分类 / 内容 / 分层 → 保存 → 抽屉与列表对应行刷新
  - **Outcome:** 修正后的内容立即生效，后续召回读到的是新版本
  - **Covered by:** R10, R11, R12, R13
  - **Failure / escape:** 保存失败时抽屉保留已编辑内容并提示原因

- F3. 删除一条记忆
  - **Trigger:** 用户认为某条记忆不该继续存在（记错、涉及隐私、已经失效）
  - **Actors:** A1
  - **Steps:** 打开详情或列表操作 → 点击删除 → 二次确认 → 该条从列表移除
  - **Outcome:** 该条记忆及其向量一并清除，不再出现在列表与召回结果里
  - **Covered by:** R14, R15
  - **Failure / escape:** 删除失败时保留原条目并提示原因

---

## Requirements

**入口与范围**

- R1. 新增独立的记忆页面，作为聊天应用内的独立路由，从侧边栏底部新增图标入口进入；该入口对所有登录用户显示。
- R2. 页面不做角色分支：不读取 keeper 状态来改变行为，也不提供「指定用户」或「全站」视角；请求始终限定为当前登录用户自己的记忆。
- R3. 本版不提供新建入口：记忆由 agent 在对话中写入，页面只承担核对、修正与清理。
- R4. 鉴权与请求失败（401/403/404/服务不可用）给出明确错误提示，不出现静默失败或空白页。

**列表与定位**

- R5. 列表以表格展示每条记忆的元数据：关键点（key）、分类（cate）、分层（tier）、重要性评分、最近访问时间与更新时间；正文不在列表里展示。
- R6. 列表分页展示并给出总数，点击行打开抽屉。
- R7. 默认按创建时间倒序；排序字段限定在后端允许的范围内，交互与语料、技能面板一致。
- R8. 提供关键字筛选（按 key 匹配）与分类、分层筛选；筛选走服务端参数，保证分页与总数正确。
- R9. 列表的空、加载中、加载失败三态齐备；没有任何记忆时给出说明性空态，而不是一句「暂无数据」。

**详情与编辑**

- R10. 抽屉展示条目全貌：正文、分类、分层，以及只读的派生信号（重要性评分、衰减率、访问计数、最近访问时间、创建与更新时间）。
- R11. 抽屉内可编辑分类、正文与分层并保存；重要性评分、衰减率、访问计数与时间字段只读，不让用户直接填写引擎的派生值。
- R12. 保存成功后刷新抽屉与列表对应行；保存失败保留编辑内容并给出可理解的原因。
- R13. key 是归属内的唯一标识且不可变更：界面不提供改名，并说明要改 key 需要删除后重建。

**删除**

- R14. 删除需二次确认，提示明确说明不可恢复、且该条不会再被 agent 召回。
- R15. 删除成功后该条从列表移除；失败时保留原条目并提示原因。

**通用**

- R16. 页面文案接入现有多语言体系，所有 locale 文件同步补齐，并满足现有的语言键一致性测试。
- R17. 复用现有请求封装、错误处理与权限守卫模式，不引入新的请求基础设施。

## Acceptance Examples

- AE1. **Covers R1, R2.** 非 keeper 用户与 keeper 用户从侧边栏进入的是同一个记忆页，两者看到的都是本人记忆；页面上不出现「指定用户」「全站」之类的视角切换。
- AE2. **Covers R5, R10.** 列表行只显示元数据、不出现正文；打开抽屉后能看到该条完整正文与只读的派生信号。
- AE3. **Covers R8.** 选择某个分类后列表只剩该分类的条目，分页总数随之变化；关键字与分层的组合筛选同样由服务端结果决定。
- AE4. **Covers R11, R12.** 修改正文并保存后，重新打开抽屉读到的是新内容；保存失败时抽屉内保留编辑后的文本并提示原因。
- AE5. **Covers R13.** 抽屉内没有 key 的编辑入口，只有「要改 key 需删除后重建」的说明。
- AE6. **Covers R14, R15.** 点击删除弹出二次确认；取消不发生任何变化，确认后该条从列表消失。
- AE7. **Covers R4.** 抽屉打开期间该条已在别处被删除时，保存或删除返回「未找到」，页面给出对应提示并刷新列表，不残留加载态。

## Success Criteria

- 用户不需要 curl 或改库就能看清系统记住了自己什么，并修正或删除其中错误的条目。
- 被删除的条目从后续对话的召回里消失；被修正的内容在后续召回里生效。
- 页面前端不做角色判断，展示内容与后端返回一致；越权与各类失败都有兜底提示。
- 需求文档足以让 ce-plan 直接产出实现方案，无需再补产品决策。

---

## Scope Boundaries

- 不做新建记忆：记忆由 agent 写入，手动创建要引入 key 冲突与分层 / 重要性默认值的语义，本版不承担。
- 不做 keeper 代查与全站视图：页面只服务用户自己的记忆，后端的指定用户与全站能力留给接口和后续的运维面。
- 不做聊天内的记忆旁路展示（例如在消息上标注本轮召回了哪些记忆）。
- 不做批量操作（批量删除、导出、导入）。
- 不展示记忆的向量与召回质量指标，不做衰减曲线可视化。
- 不改动 morrigan 后端：本版全部是 Calisyn 前端工作。

---

## Key Decisions

- 面向所有登录用户，而非 keeper-only：记忆属于个人，用户是唯一有权决定「该不该记住」的人；keeper 在本页没有额外视角。
- 页面请求始终限定为本人记忆，而不是沿用后端默认行为：后端的列表默认在 keeper 身份下返回全站，原样透传会让 keeper 在这页看到别人的记忆；前端不做角色分支，只是把请求限定为本人。
- 复用技能面板的结构（表格 + 抽屉）：列表接口默认裁掉正文、正文需单独取详情，这套数据形态正好对上。
- 用户可改的只有分类、正文、分层：重要性、衰减率、访问计数与时间字段是引擎的派生信号，让用户直接填写既没有语义，也会破坏衰减模型的判断。
- 不做新建：本版的价值在核对、纠错与清理；手动创建与 agent 的写入路径重叠，还要处理 key 冲突与默认分层。
- 删除沿用后端语义（硬删除并在同一事务内清向量），确认文案按不可恢复写。
- 列表只取元数据、正文在抽屉里单独取：避免翻页时把全部正文一并拉下来。

---

## Dependencies / Assumptions

- morrigan 已交付记忆归属与五个 HTTP 接口（列表 / 详情 / 创建 / 更新 / 删除），沿用 `{ status, result }` 信封，列表结果为 `{ data, total }`。该提交当前在 `feat/memory-ownership` 分支（fab00e2），尚未并入 morrigan 主线；上线前需确认已合并并部署。
- 列表默认不返回正文，需要正文时按 ID 单独取详情。
- 列表在未传分页参数时由服务端补默认条数（已核实 morrigan 的 `defaultMemoryPageLimit` 为 20），前端分页与之对齐。
- 越权返回 403、目标不存在返回 404、其余失败按服务不可用处理；前端只做提示映射。
- key 在归属内唯一，且更新接口不接收 key。
- 分层取值为 `working` / `short-term` / `long-term`；分类是自由文本，前端不做枚举约束。
- 新增文案需同步全部 locale 文件，并满足现有的语言键一致性测试。
